Простая инструкция: что где лежит и как этим пользоваться. Для каждой роли — свой раздел.

## 2. Роли и права

Права человека = права его **роли** + права всех его **активных групп**.

| Роль | Что может по умолчанию |
|---|---|
| **Руководитель** | всё |
| **Методист** | база знаний и одобрение, игротека, тесты, журнал, оценочные листы |
| **Мастер** | видеть заявки, журнал, тесты (проверка), оценочные листы, база, игротека |
| **Куратор** | журнал, проверка тестов, закрытая база, конструкторы |
| **Орг** | добавлять в базу и игротеку (через одобрение), конструкторы |
| **СМИ** | слайдер на главной, закрытая база, конструкторы |
| **Старик** | оценочные листы, закрытая база, конструкторы |
| **Педсостав (PRO)** | закрытая база, конструкторы |
| **Энерт** | учиться: тесты, кабинет, открытая игротека и база |

**Главные админы** прописаны в файле `.env` (`SUPERADMIN_IDS`): они всегда руководители.

### Группы

«Админка → Группы и права»:

- группа — это поток, команда мастера, орг-группа на выезд и т. п.;
- у группы есть **права** (галочки) и **срок**: когда он кончится, права пропадут сами;
- галочка **«Это поток»** включает журнал посещаемости по группе;
- участника добавляют по `@username` или Telegram id. Человек должен хоть раз войти на сайт.

## 3. Руководителям

**Запуск нового потока — 5 шагов:**

1. Энерты входят на сайт через Telegram (кнопка «Войти» или бот).
2. «Группы и права» → новая группа, например «Осенний поток 2026», галочка «Это поток», добавить участников.
3. «Журнал потока» → добавить 8 занятий (последнее отметить «аттестационное»).
4. «Тесты» → открыть тест, скопировать ссылку и отправить в чат потока.
5. После выезда и аттестации поставить отметки в карточке каждого энерта.

**Одобрение.** Всё, что орги и мастера отправили «в общую базу» (игры, материалы, разработки из конструкторов), ждёт в «Админка → На одобрении». Одобрили — появилось на сайте.

**Заявки** приходят в Telegram-чат организаторов. Кнопки под заявкой меняют её статус и на сайте.

## 4. Мастерам и кураторам

- **Посещаемость:** «Журнал потока» → «Отметить» у занятия → галочки «был» / «не был, но предупредил».
- **Зачёты, баллы, выезд, аттестация:** нажмите на имя энерта в журнале — откроется карточка.
  - Зачёты игротеки — 9 галочек по разделам.
  - «Баллы и отметки»: активность (+), штраф (−), практика, **вожатский выезд**, **аттестация сдана**.
- **Тесты:** «Тесты → Результаты». Открытые ответы читайте и ставьте «Зачёт / Незачёт» с комментарием.
- **Оценочные листы ENERGY PRO:** в карточке человека внизу — оценка 1–5 по каждому критерию.

## 5. Энертам

1. Нажмите «Войти» → «Войти через Telegram» (или откройте бота ENERGY → «Личный кабинет»).
2. В кабинете — **шкала развития**:

| Блок | Вес | Как растёт |
|---|---|---|
| Теория | 25% | зачёт по тестам после занятий |
| Игротека | 25% | зачёт по каждому из 9 разделов |
| Посещаемость | 20% | отметки мастера; не больше 3 пропусков |
| Активность | 10% | баллы рейтинга минус штрафы (20 баллов = максимум) |
| Вожатский выезд | 10% | отметка после выезда |
| Аттестация | 10% | отметка после аттестации |

Уровни: **Искра** (0%) → **Заряд** (25%) → **Энергия** (60%) → **Молния** (90%).

Веса и уровни меняются в файле `app/progress.py`.

## 6. Контент

### Игротека — «Админка → Игротека»

Название, раздел, возраст, участники, время, реквизит, текст. Разметка текста:

```
## Подзаголовок
Обычный абзац. **Жирный**, *курсив*.

- пункт списка
- ещё пункт

> «Строчка речёвки,
> вторая строчка»
```

Галочка «Открытая игра» — видна всем и в поиске Яндекса. Без неё — только команде.

### База знаний — «Админка → База знаний»

- **Доступ:** открытый (всем) / закрытый (по правам) / по закрытой ссылке.
- **Инфографика:** ключевые пункты «заголовок + пояснение» — показываются цветными карточками сверху (лучше для открытых статей).
- **Файл:** PDF, Word, PowerPoint, Excel до 50 МБ. Закрытые файлы не скачать без входа.

### Слайдер — «Админка → Слайдер»

Горизонтальные фото от 1600 px, порядок, подпись, «скрыть».

### Конструкторы — `/konstruktor`

Игра, КТД, свечка/огонёк, мероприятие для СВ. Черновик видит только автор. «Отправить в общую базу» → одобрение → видят все. Кнопка «Распечатать / PDF».

Поля конструкторов описаны в `app/constructors.py`: добавьте строку — поле появится в форме и в печати. Там же банк вопросов для свечек.

## 7. Telegram-бот (отдельный сервер)

Бот живёт на **своём сервере** и не видит базу сайта. Всё делает через API сайта (`/api/bot/…`), защищённое ключом `BOT_API_TOKEN` — он **одинаковый** в `.env` сайта и в `bot/.env`.

```
 Посетитель ──► сайт (nginx + FastAPI, сервер 1) ◄── API по ключу ──  бот (сервер 2) ◄──► Telegram
```

| Что | Как работает |
|---|---|
| Заявки | бот раз в 15 секунд спрашивает у сайта новые заявки и шлёт их в чат `LEADS_CHAT_ID`. Сайту не нужен доступ к Telegram |
| Кнопки «Связались / Зачислен / Отказ» | бот передаёт нажатие сайту, сайт проверяет права нажавшего и меняет статус |
| `/start` | кнопки: Кабинет, Игротека, База, Конструкторы — открываются внутри Telegram (это сам сайт) |
| `/igra` | случайная игра; `/igra кричалки` — из раздела |
| `/chatid` | показать id чата (для настройки) |

Вход через Telegram на сайте и в Mini App проверяется подписью по `BOT_TOKEN` прямо на сайте — для этого сайту **не нужен** выход в Telegram, только сам токен в `.env`.

Если бот не может достучаться до сайта, он пишет об этом в лог (`journalctl -u energy-bot -f` или `docker compose logs -f`), а заявки не теряются: они отправятся, как только связь появится (если ей меньше двух суток).

### Установка бота на его сервер

Скопируйте на сервер бота **только папку `bot/`**, например в `/opt/energy-bot`.

```bash
cd /opt/energy-bot
cp .env.example .env && nano .env     # BOT_TOKEN, SITE_URL, BOT_API_TOKEN, LEADS_CHAT_ID
```

**Вариант с Docker:** `docker compose up -d --build`

**Вариант без Docker:**

```bash
sudo apt install -y python3-venv
sudo useradd --system --home /opt/energy-bot --shell /usr/sbin/nologin energybot
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
sudo chown -R energybot:energybot /opt/energy-bot
sudo cp energy-bot.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now energy-bot
```

В логе при старте должно быть «Связь с сайтом … есть». Если нет — бот напишет, что не так (ключ, адрес, выключенное API).

Серверу бота нужен выход в интернет к `api.telegram.org` и к вашему сайту. Входящие порты ему не нужны.

## 8. Установка на VPS (nginx)

Схема: **nginx** на сервере принимает запросы и HTTPS, сам отдаёт картинки и стили, остальное передаёт сайту на `127.0.0.1:8000`. Сайт и бот запускаются либо через **systemd** (без Docker), либо через **Docker**. Выберите один вариант.

Команды ниже для Ubuntu/Debian. Домен в примерах — `energy-academy.ru`, папка — `/opt/energy-site`.

### Шаг 0. Подготовка

1. Домен → A-запись на IP сервера (и `www` тоже).
2. @BotFather: создать бота, `/setdomain` → ваш домен.
3. Скопировать папку `energy-site` на сервер в `/opt/energy-site`, например через WinSCP или `scp -r`.

```bash
sudo apt update && sudo apt install -y nginx certbot python3-certbot-nginx python3-venv
cd /opt/energy-site
cp .env.example .env && nano .env
```

В `.env` заполнить: `SITE_URL=https://energy-academy.ru`, `SECRET_KEY` (длинная случайная строка), `BOT_TOKEN`, `BOT_USERNAME`, `SUPERADMIN_IDS` (ваш Telegram id, узнать у @userinfobot), **`BOT_API_TOKEN`** (тот же ключ, что у бота), **`DEV_LOGIN=0`**. `LEADS_CHAT_ID` на сайте не нужен — он задаётся у бота.

Бот ставится на свой сервер отдельно — см. раздел 7.

### Шаг 1, вариант А. Без Docker (systemd)

```bash
sudo useradd --system --home /opt/energy-site --shell /usr/sbin/nologin energy
cd /opt/energy-site
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
mkdir -p data && sudo chown -R energy:energy /opt/energy-site
sudo cp deploy/systemd/energy-web.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now energy-web
```

Проверить: `systemctl status energy-web`, логи — `journalctl -u energy-web -f`.

### Шаг 1, вариант Б. В Docker

```bash
cd /opt/energy-site
docker compose up -d --build
```

Сайт будет слушать только `127.0.0.1:8000` — снаружи его видно только через nginx.

### Шаг 2. nginx

```bash
sudo cp deploy/nginx/energy.conf /etc/nginx/sites-available/energy.conf
sudo nano /etc/nginx/sites-available/energy.conf      # заменить домен и путь, если другие
sudo ln -s /etc/nginx/sites-available/energy.conf /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
```

### Шаг 3. HTTPS

```bash
sudo certbot --nginx -d energy-academy.ru -d www.energy-academy.ru
```

Certbot сам выпустит сертификат, допишет его в конфиг nginx, включит редирект на https и будет продлевать сертификат автоматически.

Готово: откройте `https://energy-academy.ru`. При первом запуске база заполнится сама (игротека, тесты, статьи, фото слайдера).

### Что делает конфиг nginx

| Что | Как |
|---|---|
| `/static/…` | css, js, картинки отдаёт сам nginx, кэш 7 дней |
| `/media/slides/…` | фото слайдера с диска (`data/uploads/slides`) |
| файлы базы знаний | только через сайт (`/files/kb/…`), чтобы закрытые материалы нельзя было скачать по прямой ссылке |
| загрузка файлов | до 50 МБ (`client_max_body_size`) |
| `www.` | перенаправляется на адрес без `www` |
| IP посетителя | передаётся сайту в `X-Real-IP` (нужно для защиты формы заявки от спама) |

### Обновление и бэкап

- **Обновить сайт:** заменить файлы → `sudo systemctl restart energy-web` (или `docker compose up -d --build`). Бот обновляется так же на своём сервере.
- **Бэкап:** копия папки `data/` (база `energy.db` и загруженные файлы `uploads/`).

### Локально на Windows

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env      # SITE_URL=http://localhost:8000, DEV_LOGIN=1, SECRET_KEY=что угодно, SUPERADMIN_IDS=1
uvicorn app.main:app --reload
```

Вход руководителем без Telegram: http://localhost:8000/auth/dev?tg_id=1&name=Admin
